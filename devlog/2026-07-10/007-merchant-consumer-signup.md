## 작업 요약

로그인 화면에 표시되던 관리자·상인·소비자 역할 안내 카드를 제거해 아이디와 비밀번호 입력에 집중하도록 정리했다.
회원가입에서는 상인 또는 소비자를 선택할 수 있게 하고, 서버와 User 계층에서도 두 역할만 허용해 관리자는 기존 admin 계정으로만 로그인하도록 제한했다.

## 원문 요청사항

```text
로그인 페이지에 관리자 상인 이거 삭제해주고, 회원가입할 때, 상인인지, 소비자인지 선택하게 해서 회원가입하게해줘. 상인도 관리자는 admin 계정 쓰면됨.
```

- 소스와 생성 번들에서 기존 로그인 역할 카드 데이터·문구가 제거됐음을 확인
- 신규 상인 회원가입이 merchant 역할 세션과 `/merchant/overview` 목적지를 반환함을 확인

- 상인 계정의 소비자 보호 API 접근과 소비자 계정의 관리자 보호 API 접근이 각자의 홈으로 리다이렉트됨을 확인

- 세션 확인 응답에 password가 노출되지 않음을 확인
- 검증용 상인·소비자 계정 2개는 테스트 직후 삭제하여 DB 원상 복구
- 대상 Python 2개 파일 AST 파싱, 역할 허용 목록 정적 검증 및 `git diff --check` 통과
- 리뷰의 `detectChanges` 로그를 별도 조사했으나 현재 루트 초기화·번들 흐름에서는 재현 경로를 확인하지 못해 공통 Service는 변경하지 않음

## 남은 리스크

- 상인 회원가입은 별도 점포 인증이나 관리자 승인 없이 즉시 merchant 권한을 부여한다.
- 관리자 초기 비밀번호는 저장소 외부의 안전한 비밀 주입 절차로 설정해야 한다.
- 실행 환경에 Headless 브라우저가 없어 실제 클릭 기반 UI·브라우저 콘솔 회귀 테스트는 수행하지 못했다.
